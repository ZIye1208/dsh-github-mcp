# dsh-github-mcp 详细修复方案

> 基线：`v0.3.1` / commit `a212ce0e5e0491e1d6b37a9eecc9efd5e438c1d0`
>
> 审查环境：DSH `0.2.2-rc.5`、Node `24.19.0`、Cordis `4.1.0`
>
> 方案日期：2026-11-26
>
> 范围：只给出可实施修复方案，不修改插件源码。文中代码片段是改造骨架，落地时需按当前 DSH 类型和现有测试补齐。

---

## 0. 先看结论

当前版本的主连接链路在 DSH `0.2.2-rc.5` 上静态兼容，npm 发布物与仓库代码一致；但存在三类需要修的问题：

1. **安全**：模型可触发 `github_token_status` 读取 PAT 并主动访问 GitHub，原始上游错误会进入模型结果；清除 token 时可能被环境变量回退“复活”；非密钥配置混入凭据中心并用 `localStorage` 回显。
2. **兼容**：缺少 `mcpManager` 的启动依赖声明；诊断代码依赖私有 API 和硬编码 Windows 路径；CI 使用 Node 22，且宿主测试在 CI 中整组跳过；`dsh-github-mcp-hint` 仍走旧的环境变量 token 链路。
3. **可优化**：工具集和只读配置保存非原子；状态工具扫描全局 MCP/工具，输出面过大；硬编码工具数会过时；测试和发布流程不够可复现。

建议按两个版本落地：

| 版本 | 目标 | 是否必须 |
|---|---|---|
| `0.3.2` | 安全止血：移除模型侧 PAT/网络探活、修清除语义、移除私有 API 和硬编码路径、补启动依赖 | 是 |
| `0.4.0` | 架构修复：非密钥配置迁到 Settings、原子保存、严格校验、迁移旧配置、移除 hint 依赖、重建 CI | 是 |
| `0.4.1` | 根据真机反馈清理兼容层和文档 | 视情况 |

**默认建议**：新安装默认开启只读模式；已有用户的旧值（包括旧版自动 seed 的 `false`）在迁移时保留，但 UI 必须给出醒目风险提示。PAT 仍使用最小权限 fine-grained token，不能把 `X-MCP-Readonly` 当作唯一授权边界。

## 2. 目标架构

### 2.1 配置归属

| 数据 | 权威存储 | 谁可读明文 | 谁可写 | 热更新方式 |
|---|---|---|---|---|
| `GITHUB_TOKEN` | DSH credentials | 仅 Host 内部模板展开/探测 | 用户在设置页写；模型不可写 | `credentials/reference-updated` → mcp-client 重连 |
| `toolsets` | 插件 volatile Config | 非密钥，Host/UI 可读 | 设置页 `settings.mutate` | `loader/volatile-update` → 插件重注册 |
| `readOnly` | 插件 volatile Config | 非密钥，Host/UI 可读 | 设置页 `settings.mutate` | 同上 |
| `serverName` | 插件 volatile Config | 非密钥 | 设置页高级选项或 yml | Host 重注册；工具命名空间变化，需重开会话 |
| MCP URL | 代码常量 | 非密钥 | 不可配置 | 固定 `https://api.githubcopilot.com/mcp/` |

**不再使用**：

- `GITHUB_MCP_TOOLSETS` / `GITHUB_MCP_READONLY` 作为运行时权威配置；
- `localStorage` 作为工具集/只读当前值；
- 模型工具中的 `credentials.resolve("GITHUB_TOKEN")`；
- 插件直接 `fetch` GitHub；
- loader 私有 fiber/status cell 扫描。

### 2.2 连接生命周期

```text
设置页保存工具集/只读
  └─ ctx.remote.settings.mutate(ns, ops, expectedRevision)
       └─ 一次 profile 写入，两个字段同时生效
            └─ loader/volatile-update(paths)
                 └─ Host 串行执行 registerCurrent()
                      ├─ stop 旧注册
                      └─ mcpManager.register(serverName, {
                           transport: 'streamable-http',
                           url: 固定 GitHub MCP,
                           headers: {
                             Authorization: 'Bearer ${credential:GITHUB_TOKEN}',
                             'X-MCP-Toolsets': toolsets.join(','),
                             'X-MCP-Readonly': String(readOnly)
                           }
                         })
```

Token 变化仍由 mcp-client 自己监听凭据事件并刷新，不需要插件重注册。

### 2.3 诊断边界

`github_token_status` 变成纯本地状态查询：

- token：只返回 `configured/source/writable`，不返回 PAT，也不返回掩码；
- 配置：返回当前 `toolsets/readOnly/serverName`；
- 连接：只返回 manager 中当前 `serverName` 的状态和 `toolCount`；
- 不访问网络，不读取其它 server，不枚举全局工具，不导入 mcp-client 私有模块。

“测试连接”放到设置页，作为**用户主动操作**：调用 `ctx.remote.mcpManager.probe(serverName)`。该公共 API 会使用当前注册配置、完成 MCP 协商、列出工具并关闭独立连接，比手写 `initialize` 更完整。

## 3. P0：`0.3.2` 安全止血

这一阶段不迁移配置存储，以最小改动先消除高风险面。

### 3.1 `lib/index.mjs`

#### 3.1.1 删除模型侧 PAT 与网络逻辑

删除或不再调用：

- `resolveValue()` 对 `GITHUB_TOKEN` 的使用：P0 阶段仍需读取两个非密钥选项，可将 helper 收窄为 `resolveOption(ref)`，并用白名单只允许 `GITHUB_MCP_TOOLSETS/GITHUB_MCP_READONLY`；
- `probe()`：`:73-85`；
- `describeErrorChain()`：`:88-99`；
- `github_token_status` 中 `:206-250` 的 `/user` 和 MCP `initialize` 探活；
- `:252-300` 的 loader 扫描；
- `:302-317` 的全局工具视图。

保留：

- `credentials.describe("GITHUB_TOKEN")`；
- 当前工具集/只读配置读取；
- `mcpManager.list()` 中当前 server 的状态。

建议返回结构化对象，而不是拼接大段文本：

```js
async function execute() {
  const token = await ctx.credentials.describe('GITHUB_TOKEN')
  const serverName = 'github' // P0 尚未引入 serverName Config
  const server = ctx.mcpManager.list().find((row) => row.name === serverName)

  return {
    token: {
      configured: token?.configured === true,
      source: token?.configured ? token.source : undefined,
      writable: token?.writable === true,
    },
    toolsets: parseToolsets(await resolveOption(ctx.credentials, 'GITHUB_MCP_TOOLSETS')),
    readOnly: (await resolveOption(ctx.credentials, 'GITHUB_MCP_READONLY')) === 'true',
    serverName,
    connection: server ? sanitizeManagedStatus(server.status) : { state: 'not-registered' },
  }
}
```

`sanitizeManagedStatus()` 只保留允许的字段，例如 `state/toolCount/connectedAt`；如保留 `lastError`，必须经过统一脱敏和限长。返回对象时，工具 `output.schema` 和 `render` 也要从字符串改成对应对象结构，不能只改 `execute()`。

#### 3.1.2 启动依赖改为硬依赖

```js
export const inject = ['credentials', 'tools', 'mcpManager']

export async function apply(ctx, config) {
  await seedCredentialDefaults(ctx, config)
  registerServer(ctx, config)
  // ...
}
```

`registerServer()` 不再使用 `ctx.get('mcpManager')` 做静默降级。缺服务时应让插件在版本门或启动检查中明确失败，而不是“插件活着但工具没有”。

#### 3.1.3 移除注册 entry 的 `enabled`

当前 `manager.register()` 的公共输入类型是 `McpServerRegistration = Omit<EntryInput, 'enabled'>`，manager 内部会强制 `enabled:true`。删除：

```js
// 删除，不属于公共注册输入
enabled: true,
```

#### 3.1.4 统一日志脱敏

所有 `logger.warn/error` 不直接打印 `error.message`。建立：

```js
function safeDiagnostic(error, max = 500) {
  const text = String(error?.message ?? error ?? 'unknown error')
    .replace(/(gh[pousr]_[A-Za-z0-9_]+|github_pat_[A-Za-z0-9_]+)/gi, '[REDACTED]')
    .replace(/Bearer\s+\S+/gi, 'Bearer [REDACTED]')
  return text.slice(0, max)
}
```

### 3.2 `lib/client.js`

#### 3.2.1 修正清除 token 的语义

当前实现 `unset` 后无条件提示“已清除”。改为：

```js
async function clearToken() {
  if (busyRef.current) return
  busyRef.current = true
  setBusy(true)
  setNotice(null)
  try {
    await call(ctx.remote.credentials.unset(TOKEN_REF))
    const data = await reload()
    const info = data?.[TOKEN_REF]
    if (info?.configured && info.source !== 'file') {
      setNotice({
        kind: 'warning',
        text: t('clearedButFallbackActive', { source: formatCredentialSource(info.source) }),
      })
    } else if (info?.configured) {
      setNotice({ kind: 'error', text: t('tokenClearFailed') })
    } else {
      setNotice({ kind: 'ok', text: t('cleared') })
    }
  } finally {
    busyRef.current = false
    setBusy(false)
  }
}
```

新增文案必须覆盖四种来源：

- `file`：凭据文件；
- `env`：启动环境变量；
- `project-env`：项目 `.env`；
- `user-env`：用户 `.env`。

如果来源是 `env`，提示“删除启动环境变量并重启 DSH 后才会完全失效”；不要假装插件可以修改宿主启动环境。

#### 3.2.2 前端错误不再裸抛

建立 `toNotice(error)`：

- 已知错误映射到本地文案；
- 未知错误只显示通用错误码；
- 详细诊断写入 Host 脱敏日志，不在 UI 回显 `error.message`。

### 3.3 `README.md` / `README.en.md`

P0 必须同步修正：

- 状态工具只调用 `describe()`，不读取 PAT；
- 状态工具不主动访问 GitHub；
- 清除 token 可能暴露环境变量 fallback；
- Windows 上凭据文件权限依赖宿主实现和 ACL，不能承诺等同于 POSIX `0600`；
- `X-MCP-Readonly` 是 GitHub MCP 的工具过滤开关，不是 PAT 权限替代品。

### 3.4 P0 验收

- [ ] 调用 `github_token_status` 时，Host 不出现 `credentials.resolve("GITHUB_TOKEN")`。
- [ ] 调用状态工具不产生任何 GitHub HTTP 请求。
- [ ] 状态结果不含 PAT、token 掩码、其它 server 名、全局工具名。
- [ ] 删除源码中所有 `file:///H:/...` 和 `cell.value` 私有访问。
- [ ] `inject` 包含 `mcpManager`。
- [ ] 设置 `GITHUB_TOKEN` 环境变量后点击清除，UI 显示 fallback 警告，而不是“已清除”。
- [ ] 日志和 UI 均不含 PAT。

### 4.2 `lib/config.mjs`

把配置解析改成严格、可复用函数：

```js
export const DEFAULT_CONFIG = Object.freeze({
  toolsets: Object.freeze(['repos', 'issues']),
  readOnly: true,
  serverName: 'github',
})

const TOOLSET_IDS = new Set(TOOLSETS.map((item) => item.id))

export function normalizeToolsets(value) {
  const list = Array.isArray(value)
    ? value.map((item) => String(item).trim()).filter(Boolean)
    : String(value ?? '').split(',').map((item) => item.trim()).filter(Boolean)

  const normalized = [...new Set(list)]
  if (normalized.length === 0) throw new TypeError('TOOLSETS_EMPTY')
  const unknown = normalized.filter((id) => !TOOLSET_IDS.has(id))
  if (unknown.length > 0) throw new TypeError(`TOOLSETS_UNKNOWN:${unknown.join(',')}`)
  return normalized
}

export function normalizeReadOnly(value) {
  if (typeof value === 'boolean') return value
  if (value === 'true') return true
  if (value === 'false') return false
  throw new TypeError('READONLY_INVALID')
}
```

删除 `credentialDefaults()` 或仅迁移期使用。运行时不再 seed 两个非密钥凭据引用。

### 4.3 `lib/index.mjs`

#### 4.3.1 导出 Config

```js
import Schema from '@deepseek-ai/schemastery'
import { DEFAULT_CONFIG, TOOLSETS } from './config.mjs'

const Toolset = Schema.union(TOOLSETS.map((item) => item.id))

export const Config = Schema.object({
  toolsets: Schema.array(Toolset)
    .min(1)
    .default([...DEFAULT_CONFIG.toolsets])
    .volatile(),
  readOnly: Schema.boolean()
    .default(DEFAULT_CONFIG.readOnly)
    .volatile(),
  serverName: Schema.string()
    .pattern(/^[A-Za-z0-9_-]{1,32}$/)
    .default(DEFAULT_CONFIG.serverName)
    .volatile(),
})

export const inject = ['credentials', 'tools', 'mcpManager']
```

三个字段都使用 volatile，设置页才能读到并原子保存。`serverName` 变化会改变工具命名空间，Host 会重注册；UI 必须明确提示“需重开会话”，并避免用户误改。P1 中所有配置读取都要改为 `.get()`，包括状态工具内的 `toolsets/readOnly/serverName`。

#### 4.3.2 注册与重注册

```js
export function apply(ctx, config) {
  let stop = null
  let registrationGeneration = 0
  let registerQueue = Promise.resolve()

  function registerCurrent() {
    registerQueue = registerQueue.then(() => {
      stop?.()
      stop = null
      const generation = ++registrationGeneration

      try {
        stop = ctx.mcpManager.register(config.serverName.get(), {
          transport: 'streamable-http',
          url: 'https://api.githubcopilot.com/mcp/',
          headers: {
            Authorization: 'Bearer ${credential:GITHUB_TOKEN}',
            'X-MCP-Toolsets': config.toolsets.get().join(','),
            'X-MCP-Readonly': String(config.readOnly.get()),
          },
        })
      } catch (error) {
        const log = typeof ctx.logger === 'function' ? ctx.logger('dsh-github-mcp') : ctx.logger
        log?.warn?.('failed to register GitHub MCP: %s', safeDiagnostic(error))
        if (generation === registrationGeneration) stop = null
      }
    })
    return registerQueue
  }

  ctx.on('loader/volatile-update', (paths) => {
    if (paths.some((path) => ['toolsets', 'readOnly', 'serverName'].includes(path[0]))) {
      void registerCurrent()
    }
  })

  ctx.effect(() => () => {
    registrationGeneration += 1
    stop?.()
  })

  ctx.inject(['settings'], (child) => {
    child.effect(() => child.settings.configure({ auto: false }, ctx.fiber))
  })

  void registerCurrent()
  registerStatusTool(ctx, config)
  void migrateLegacyOptions(ctx, config)
}
```

注意：

- `manager.register()` 的 disposer 要由插件持有，重注册前先 `stop()`；
- 使用串行队列避免快速多次保存造成注册交错；
- 同名冲突不要静默切换名字，应返回 `SERVER_NAME_CONFLICT`，提示用户修改 `serverName` 后重开会话；
- 不要监听 `internal/update` 来处理 volatile 变化，volatile-only 更新不走该 waterfall。

#### 4.3.3 旧配置迁移

迁移只发生在首次运行新版本，且必须可回滚：

1. 检查用户 Config 是否已经显式包含 `toolsets/readOnly`；
2. 如果未包含，读取旧凭据 `GITHUB_MCP_TOOLSETS/GITHUB_MCP_READONLY`；
3. 用严格解析校验；非法值忽略并记录脱敏警告；
4. 通过 `ctx.inject(['configEditor'], child => child.configEditor.edit(ctx.fiber.entry, current => ({ ...current, toolsets, readOnly })))` 写入，避免未注入服务；
5. 因为字段是 volatile，写入会触发 `loader/volatile-update`，Host 自动重注册；
6. **不自动 unset 旧凭据引用**，保证回滚到 0.3.1 时旧版本仍能读到原配置；
7. 不自动删除 localStorage 旧键，保证回滚兼容；新版本只是不再读取。

建议迁移在初始注册和事件监听建立后执行，避免重入；首启最多发生一次额外重连，可接受。

#### 4.4.2 原子保存

```js
async function saveOptions() {
  if (busyRef.current || draftToolsets.length === 0) return
  busyRef.current = true
  setBusy(true)
  setNotice(null)

  const toolsets = normalizeToolsets(draftToolsets)
  const readOnly = draftReadOnly === true

  try {
    const next = await call(ctx.remote.settings.mutate(
      'dsh-github-mcp',
      [
        { op: 'set', path: ['toolsets'], value: toolsets },
        { op: 'set', path: ['readOnly'], value: readOnly },
      ],
      view.revision,
    ))

    setView(next)
    setDraftToolsets(next.value.toolsets)
    setDraftReadOnly(next.value.readOnly)
    setNotice({ kind: 'ok', text: t('optionsSaved') })
  } catch (error) {
    if (isSettingsConflict(error)) {
      setNotice({ kind: 'warning', text: t('settingsConflict') })
      await reload().catch(() => {})
    } else {
      setNotice(toNotice(error))
    }
  } finally {
    busyRef.current = false
    setBusy(false)
  }
}
```

`expectedRevision` 必须传，防止两个设置页标签页互相覆盖。

#### 4.4.3 跨标签页同步

组件挂载时订阅：

- `settings/document-updated`：重新 `settings.describe()`；
- `credentials/reference-updated`：重新 `credentials.describe()`；
- `mcpManager.watch(signal)`：更新当前 server 的连接状态。

组件卸载时：

- 退订事件；
- Abort watch/probe；
- 清理定时器。

#### 4.4.4 “测试连接”按钮

新增用户按钮：

```js
const result = await call(ctx.remote.mcpManager.probe(view.value.serverName))
```

展示规则：

- 成功：显示 `durationMs/toolCount/closeConfirmed`；
- 失败：只显示阶段和脱敏后的短消息；
- 不把 probe 的原始 `message/cleanupError` 直接写日志；
- 不把 probe 暴露为模型工具。

#### 4.4.5 严格交互

- `busyRef = React.useRef(false)` 作为同步锁；
- 所有异步操作带代次或 AbortSignal，避免旧请求覆盖新状态；
- `described.writable === false` 时禁用保存/重置；
- token 来源覆盖 `file/env/project-env/user-env`；
- 删除硬编码工具数，连接后显示真实 `toolCount`；
- `readOnly === false` 时显示风险提示，并提供“开启只读”快捷操作。

## 6. 迁移与回滚

### 6.1 从 0.3.1 升到 0.4.0

| 场景 | 迁移行为 |
|---|---|
| 用户未改过工具集/只读 | 旧引用仍是默认 `repos,issues/false`；迁移后显式保留 `false`，UI 提示可开启只读 |
| 用户改过工具集/只读 | 严格校验后迁入 Config，行为保持不变 |
| 旧值非法 | 不迁移非法值，使用安全默认并记录警告 |
| 用户已有 Config 字段 | 以用户 Config 为准，不被旧凭据覆盖 |
| token | 不迁移，仍读 `GITHUB_TOKEN` |
| 环境变量 token | 继续按宿主优先级生效；UI 显示来源 |

### 6.2 回滚到 0.3.1

- 旧凭据引用保留，因此 0.3.1 仍能恢复原工具集/只读；
- 不自动删除 localStorage 旧键，因此旧 UI 仍能回显；
- Config 是旧版本不认识的字段，但旧版本仍从凭据引用取值；
- **新安装 0.4.0 后回滚 0.3.1 是例外**：新安装没有旧凭据引用，0.3.1 会重新 seed 默认值，可能丢失 0.4.0 的只读设置。文档需明确建议不要回滚新安装。

### 6.3 旧引用清理

建议在 `0.5.0` 或更晚：

1. 先观察一个完整发布周期；
2. 提供“清理旧配置”用户操作；
3. 清理前导出/展示当前值；
4. 允许失败重试；
5. 不在升级时自动 unset。

- CI 不依赖作者本机路径。

做到这六条，后面的兼容性、测试和发布都会简单很多。
